# Voice input (iOS)

Hold the composer (or its microphone) and speak; release. Text lands in
the composer at the caret — it is **never sent automatically**. Slide up
past 64 pt: the composer itself turns red and shows "release to cancel";
releasing there discards the take and **clears the composer**.

The interaction mirrors the DeepSeek app: the collapsed bar reads
"Message or hold to talk" and can be held directly, and the recording
face lives inside the composer instead of a floating overlay.

## Why this folder exists

This is a deliberate exception to the mobile convention that domain
components live in `components/<domain>/`. The feature is owned outside the
upstream mobile surface, so it is kept as one vertical slice that can be
found by searching `VoiceInput` / `voice-input`, and removed by deleting
this folder plus the five integration points below.

## Integration points (all outside this folder)

1. `components/composer/message-composer.tsx` — renders the mic, the live
   transcript, the recording strip, the overlay, and the permission sheet.
   The shared composer powers both chat and issue comments, so both get the
   feature at once.
2. `app.config.ts` — `expo-speech-recognition` plugin + the two permission
   strings (`NSMicrophoneUsageDescription`,
   `NSSpeechRecognitionUsageDescription`). iOS/ is generated by prebuild.
3. `lib/i18n/resources.ts` — registers the `voiceInput` namespace using the
   JSON in `locales/`.
4. `vitest.config.ts` — adds `features/**/*.test.ts` to the test include.
5. `tailwind.config.js` — adds `./features/**/*.{ts,tsx}` to the content
   globs so NativeWind generates the classes used here.

Native dependency: `expo-speech-recognition@^57.1.1` (SDK 57 line). Adding
it requires a fresh dev build (`./scripts/ios-run.sh`); OTA/Expo Go cannot
load the new native module.

## State machine

```
idle ──press──▶ starting ──permission ok──▶ recording ──slide ≥64pt──▶ armed
                                                ▲   ◀── back <64pt ────┘
release:
  recording  → transcribing → insert transcript (composer keeps draft)
  armed      → discard take + clear composer
```

- `<600 ms` is treated as an accidental tap (no transcript).
- `60 s` auto-stops and transcribes; the last 10 s are shown as remaining.
- Backgrounding / phone calls cancel the take.
- The mic button stays mounted for the whole gesture; the composer hides
  the other toolbar actions with styles, never by unmounting the button.

## Tuning

`config.ts` holds every number: cancel threshold, min/max duration, meter
interval, commit timeout. `lib/insert-transcript.ts` owns the insertion
rules (caret, selection replacement, CJK/Latin spacing) and is covered by
unit tests.

## Engine seam

`engines/types.ts` defines `SpeechEngine`. `engines/apple-speech.ts` is the
v1 implementation (Apple dictation through `expo-speech-recognition`). A
server-side Whisper engine only needs to implement the same interface and
be swapped in `use-voice-input.ts`.

## Known limits (v1)

- The composer must be expanded to reach the mic; the collapsed pill only
  expands the composer today.
- Dictionary/contextual bias is not wired yet (the engine accepts
  `contextualStrings`; pass workspace names there when needed).
- `requiresOnDeviceRecognition` defaults to `false` (Apple online dictation
  has better punctuation). Flip it in `apple-speech.ts` for strict offline
  use.
